### 1. SysGuard

**Lightweight Centralized Infrastructure Monitoring and Remote Management Platform**

SysGuard is my final-year infrastructure engineering project. It explores centralized monitoring and remote management of Linux servers, with an emphasis on reducing the need for physical visits to server locations.

Key capabilities and areas of implementation:

- Linux server monitoring and system metrics.
- Server availability and failure detection.
- Remote administration and diagnosis.
- Controlled service recovery.
- Event logging and alerting.
- Infrastructure observability.

**Technologies:** Linux, Python, Docker, Prometheus, Grafana, Node Exporter, SQLite, Telegram, GNS3 and VyOS.

`Monitor → Detect → Remotely Access → Diagnose → Recover → Verify → Record / Alert`

## Engineering Approach

I want my repositories to explain the engineering behind a solution, not simply demonstrate that a particular technology was used.

Where appropriate, I structure project documentation around:

1. Problem definition
2. Requirements and constraints
3. Architecture and design decisions
4. Implementation
5. Testing and validation
6. Failure analysis and troubleshooting
7. Security considerations
8. Results and limitations
9. Lessons learned

I value clear documentation, reproducible configurations, architecture diagrams, testing evidence and explanations of technical trade-offs.

My goal is for each repository to demonstrate not only what I built, but why I built it, how it works and what I learned.
